# CORE-037 FE/BE API compatibility

Snapshot: BE `origin/feat/CORE-006-flow3-medical-contract:docs/api/flow3-medical.openapi.yaml` (unmerged draft), BE `origin/feat/CORE-026-incident-presession-gate:src/main/java/com/racehorse/core026/{Core026Controller,Contracts,AccessPolicy}.java`, BE `origin/feat/CORE-035-medical-case-treatment-recovery:src/main/java/com/racehorse/core035/{MedicalController,MedicalDtos,MedicalPorts}.java`, FE `origin/feat/CORE-036-vet-medical-groom-ui:src/features/medical/{models,service,runtimeClient,runtime}.ts(x)`. Shared approved sources: BE `origin/dev:docs/api/{shared.openapi.yaml,permission-matrix.md}`. Status describes the inspected source, not production integration.

| Area / contract operation | FE ↔ BE status | Evidence and consequence |
|---|---|---|
| `reportIncident`, `listIncidents`, `getIncident`: POST/GET `/api/incidents`, GET `/api/incidents/{incidentId}` | **MATCHED paths; BLOCKED FE** | CORE-026 controller implements all three. FE `listIncidents()` is in-memory mock; no HTTP adapter or FE create/review operation. Contract Incident POST requires numeric `horseId`, `incidentType`, `observedSeverity`, `observedAt`; actor/code/status are server-generated. |
| `reviewIncident`: POST `/api/incidents/{incidentId}/review` | **MISMATCHED** | CORE-006 requires Vet action `OPEN_CASE`, `LINK_CASE` or `RESOLVE`; CORE-026 controller exposes no review mapping. Exact transitions remain G3. FE incident page is review context only. |
| `createMedicalCase`, `listMedicalCases`, `getMedicalCase` | **MATCHED BE paths; MISMATCHED FE DTO** | CORE-035 has POST/GET `/api/medical/cases`, GET `/{caseId}`; numeric int64 IDs. FE `models.ts` uses string IDs and sample codes `MED-02`/`ST-014`. Case detail BE aggregates `incidentIds`, examinations, injuries, plan, re-exams; FE draft `MedicalCase` has singular `incidentId`, with richer `CaseView` only in mock. |
| `createMedicalExamination`: POST `/api/medical/cases/{caseId}/examinations` | **MATCHED path; MISMATCHED required input** | BE `ExamCreate` requires `symptoms` and `examinedAt`, severity `MILD/MODERATE/SEVERE`; FE draft `examinedAt?`, arbitrary severity string and mock `Mild`. |
| `createInjury`: POST `/api/medical/cases/{caseId}/injuries` | **MATCHED path; MISMATCHED DTO** | BE requires region, clinical severity and recovery state. BE/SQL store `position3d` as opaque `VARCHAR(100)` and optional `side`/exam ID. FE uses `{x,y,z}` coordinates and `clinicalNotes`; no approved encoding or injury notes column (G4). 2D region text remains a usable fallback; interactive 3D persistence blocked. |
| `getTreatmentPlan`, `putTreatmentPlan`: GET/PUT `/api/medical/cases/{caseId}/treatment-plan` | **MATCHED paths; MISMATCHED DTO/workflow** | BE requires `treatmentMedicationInstructions` text and optional `restInstructions`, `careInstructions`, `groomTasks` with `taskDate`. FE has medication array, optional rest, Groom tasks with `dueAt`. CORE-035 refuses nonempty `groomTasks` (409) until assignment/materialization policy G1. |
| `getMyTreatmentTasks`, `listTreatmentCaseTasks`, `completeTreatmentTask` | **MATCHED paths; MISMATCHED completion** | BE returns paged Groom safe projection and accepts `{}` only for POST `/api/groom/treatment-tasks/{taskId}/complete`; FE expects completion notes. DB has no note column (G2). Groom assignment adapter is absent; list/completion fail closed with 403. No task-detail GET is contracted; FE selects detail from its scoped list. |
| `createReexamination`, `closeMedicalCase` | **MATCHED paths; BLOCKED flow** | BE POST `/{caseId}/re-examinations` requires `recoveryStatus`, `findings`, `examinedAt`; FE marks timestamp optional. POST `/{caseId}/close` exists. Neither action lifts a restriction. |
| `createMedicalRestriction`, `getHorseTrainingAvailability`, `liftMedicalRestriction`, `replaceRestrictionExerciseRules` | **BLOCKED** | CORE-006 draft paths: POST `/api/horses/{horseId}/medical-restrictions`, GET `/api/horses/{horseId}/training-availability`, POST `/api/medical/restrictions/{restrictionId}/lift`, PUT `/api/medical/restrictions/{restrictionId}/exercise-rules`. CORE-019/020 absent from inspected refs; CORE-036 does not implement these screens. AVAILABLE is derived only after explicit lift/no active restriction. |
| Status and enums | **MISMATCHED / UNVERIFIED** | SQL/BE case `OPEN/CLOSED`, incident `REPORTED/UNDER_REVIEW/RESOLVED`, injury/exam `MILD/MODERATE/SEVERE`, recovery `NOT_RECOVERED/IMPROVING/RECOVERED`, restriction `LIMITED/LOCKED`, Groom task `PENDING/COMPLETED`. FE mock uses case/task states but also `Mild` and string sample IDs. Full UI mapping not verified against a live response. |
| Envelope, errors, pagination | **MATCHED BE shape; UNVERIFIED FE HTTP** | CORE-001 `ApiResponse.ok` returns `{success:true,data}`; errors are `{success:false,error:{code,message,details}}` via `GlobalExceptionHandler`. BE case/incident/task lists use `items,page,size,totalElements`, 0-based page, size 1–100. FE `ApiEnvelope` omits `details` and `MedicalService.listCases()` flattens to an array; no real parser, status handling or pagination UI adapter exists. |
| Authentication and role permissions | **BLOCKED runtime** | Merged permission matrix: Vet sole clinical writer; HT/TR/WR/GR may report Incident subject to scope; CM/HT/TR receive summaries; Groom only assigned safe task projection; no owner clinical access. CORE-026/035 need CORE-007 actor resolver; no production adapter. FE calls `GET /api/auth/me` and guards routes, but CORE-008 JWT/runtime is absent. FE guard is usability only. |
| Row scope / client actor identity | **MATCHED design; UNVERIFIED live** | CORE-026 limits TR/WR/GR incident reads to own reports and enforces work context. CORE-035 applies Trainer SQL scope and Groom trusted assignment. Request DTOs omit actor ID; unknown incident/medical fields are rejected. Trust adapters and real JWT/SQL tests are missing. |
| Abnormal pre-check | **MISMATCHED; BLOCKED** | CORE-005 draft says `ABNORMAL` automatically creates Incident/notification and sets `incidentId`. CORE-026 persists ABNORMAL, blocks start, rejects nested incident, requires explicit POST Incident; notification delivery is absent. Original approved BR-23/DEC-007 text unavailable. Do not automate either behavior until reconciled. |
