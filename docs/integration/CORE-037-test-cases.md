# CORE-037 integration cases

All HTTP paths below exist in the inspected CORE-006 draft or CORE-003 shared contract. They are **provisional test definitions**, not claims of approved/merged service availability. Use only an isolated SQL Server test database, approved seeded actors and a disposable horse. Record response IDs as test evidence; never use mock IDs. No test may report PASS until its real calls, reload and relevant SQL reads run.

For P01–P11, the intended sequence is provisional: `reportIncident` → `reviewIncident` or `createMedicalCase` with approved link → `createMedicalExamination` → `createInjury` → `putTreatmentPlan` → `createMedicalRestriction` → Groom task completion → `createReexamination` → explicit `liftMedicalRestriction` → availability read → FE reload. The missing `reviewIncident`, task assignment and restriction implementations break this sequence. No test script invents replacement endpoints or inserts data around the service.
